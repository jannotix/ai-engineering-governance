# Contributing

Contributions should preserve:

- provider neutrality;
- clear role boundaries;
- minimal process overhead;
- executable verification over narrative claims;
- backward-compatible project-state changes where practical;
- no provider-specific behavior in the core workflow.

Before opening a pull request:

1. Validate JSON and Markdown frontmatter.
2. Confirm plugin paths are relative and portable.
3. Keep commands concise and deterministic.
4. Do not introduce provider-specific model IDs.
5. Update the changelog for user-visible behavior changes.
